# CYBREX Presence v2.1.0-rc4

> Release Candidate / Pre-release. This build is intended for real-device validation before the first stable v2.1.0 release.

## Why RC4

RC4 incorporates the latest launch-readiness stack plus fixes discovered during real Linux testing after RC3.

### Resource / RAM hardening

- Replaces request-per-thread behavior in high-frequency loopback integrations with fixed worker pools.
- Bounds pending local HTTP work and client socket timeouts.
- Applies the fixed-worker implementation to Browser Companion, CS2 and shared loopback integrations.
- Reuses one persistent GUI diagnostics worker instead of creating a new thread every periodic probe.
- Prevents multiple Control Panel processes from being opened accidentally by the same user.
- Reduces Browser Companion background/mutation publishing pressure while preserving activity freshness.
- Adds stress/regression tests for bounded worker behavior.

### Desktop UI and Arabic

- Adds an updated higher-contrast desktop control panel.
- Fixes common Arabic mojibake and mixed Arabic/Latin rendering on Tk/Linux using Arabic shaping and BiDi handling.
- Prefers Arabic-capable fonts when available.
- Uses clearer Start / Restart / Stop service states.
- Improves light/dark palette, cards, navigation and diagnostics presentation.

### Gaming and integrations

- Includes the curated popular-game compatibility catalog from the current release-candidate stack.
- Preserves Steam, Epic and Heroic metadata as authoritative when available.
- Keeps game compatibility claims separate from enhanced live-telemetry claims.
- Includes Browser Companion, CS2 GSI, League, FiveM and Minecraft integration work from the current candidate stack.

## Validation gates

The RC4 publication workflow must pass before GitHub Release creation:

- full Python regression suite;
- critical Ruff checks;
- dependency consistency check;
- pip-audit dependency audit;
- high-severity Bandit gate on Linux;
- packaged Windows executable smoke test;
- Windows installer build, silent install, packaged launch and uninstall;
- packaged Linux executable smoke test;
- Linux user-level bundle install, packaged launch and uninstall;
- Browser Companion JavaScript/manifest validation;
- SHA-256 verification of all release assets before publication.

## Release status and limitations

- RC4 is **not** the stable v2.1.0 release.
- Windows artifacts may remain unsigned if Authenticode secrets are not configured; this is allowed for the prerelease but stable publication remains blocked by policy until signing is configured.
- CI cannot prove all real-device behavior. Final stable promotion still requires real Windows/Discord and Linux compositor validation plus a longer real-device soak.
- Do not interpret Standard game compatibility entries as a claim of game-specific live telemetry.

## Linux real-device focus

After installing the public RC4 asset, validate:

- RAM/RSS remains bounded during normal Discord + browser use;
- tray and Control Panel do not multiply processes;
- Arabic/mixed-direction activity text is readable;
- Discord reconnect and service restart work;
- Browser Companion stale tabs expire/clear correctly;
- KDE/Wayland foreground detection behaves as documented on supported setups.

## Integrity

The GitHub Release publishes per-file SHA-256 files plus a combined `SHA256SUMS.txt` and `BUILD-PROVENANCE.txt`. Verify checksums before installation.
